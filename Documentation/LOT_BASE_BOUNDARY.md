# Lot base boundary and exterior overlays

The Lot Editor previously rendered the terrain heightfield's two-metre storage apron outside each lot. Applying a whole-lot base such as Brick Paving colored that apron beyond the yellow lot boundary. The visible ground mesh and its collider now use only the lot footprint. The height grid retains its two-metre apron for sampling and editing, so existing terrain save data is unchanged. This applies to every Base choice and to both standalone and district-hosted lots.

Overlays remain independent surface quads and are not clipped by the base boundary. The Overlays paint tool accepts cells within the lot and one 10 m tile ring immediately outside it. Painting from an edge tile into that ring makes a continuous driveway or path reaching a road beyond the lot. Existing overlay rotation, selection, deletion, saved IDs and manual Save behavior remain in use. Other props and Garden pieces were not clipped or constrained by this change.

Validation in `Validation/lot-base-boundary-v01/`: an isolated 30 × 30 m Lot fixture with Brick Paving has visible ground bounds exactly ±15 m, and a temporary Brick Paving overlay renders outside the east boundary. Its session JSON was unchanged during capture; no Save occurred. Two focused Unity EditMode tests passed, covering the bounded mesh, overlay painting across the edge, saved cell coordinates, Brick Paving resources and prior base/overlay persistence. The temporary fixture and Editor QA code were removed. Physical pointer placement and a live saved-lot reload remain for user testing; forest/regional suites do not cover this work.
