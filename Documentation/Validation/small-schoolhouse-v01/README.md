# Small Schoolhouse V01 validation — September 18, 2026

The original four-facing hybrid prototype described below was superseded by a real-time 3D import. The active Civics / Education entry now loads the supplied FBX and PBR maps; eight newly rendered views are used only at district LOD4 and LOD5. The isolated Unity review project passed three targeted EditMode tests for 3D resources, actual lot placement, and Civics lot serialization (`small-school-3d-tests.xml`). No lot, district, or region was saved.

Metal offscreen captures from the actual lot placement show the source mesh with its color, normal, and metallic maps from two front directions (`school-3d-front-right.png`, `school-3d-front-left.png`). Corresponding far captures (`school-far-front-right.png`, `school-far-front-left.png`) show the directional image aligned to the same entrances. The visual check caught and resolved a reversed quad face and Unity's default power-of-two rescaling of cropped textures. These are isolated studio captures, not a dense Testy District 9 profiling pass. Scale beside established 3D buildings, night lighting, rotated district lots, and long-duration performance remain unverified.

Historical hybrid prototype: its V2 package imported successfully in the isolated Regions Review Unity 6.1 Metal project. One targeted EditMode test passed: package loaded in Civics / Education, four neutral resources resolved, and the source-derived proxy retained the cupola above 10.8 m. That package is no longer active.

Historical UI check: a temporary hybrid-library button exposed the prototype. The final Buildings tool now opens the real-time 3D library. New-lot and lot-settings menus offer Civics, and its contract round-trips through session serialization without renumbering older lot types. The earlier test result remains in `civics-lot-tests.xml` for provenance.

A fresh in-memory 4 × 4 lot confirmed placement. Four stable camera captures show distinct building facings at turns 0–3 with no missing texture, floating art, or split cupola. The formal front entrance is visible at default turn 0. An additional capture places the school beside the established New England House: its one-story scale reads smaller, with the bell cupola above the roof. This is provisional visual calibration, not final scale approval.

Morning and afternoon captures at turn 0 show the existing directional shadow treatment changing with the sun. A morning capture at turn 1 was also inspected, but the follow-on automated capture did not finish; afternoon and the remaining rotated shadow pairs are unverified. The projected proxy retains the complete authored height by mesh inspection and Unity resource bounds. Dense-instance CPU, allocation, draw-call and long-duration profiling were not run; no performance claim is made beyond the asset counts. The proxy is 3,494 vertices and 6,285 faces, plus two simple semantic volumes.

The prototype Blender build script regenerated all five neutral PNGs with identical pixels; PNG and FBX container hashes may vary with exporter metadata. The source archive and maps were verified byte-for-byte after extraction using the hashes in `Documentation/Migration/small-schoolhouse-v01-source-manifest.json`. The unmodified source archive is tracked under `Documentation/Migration/SourceArchives/SmallSchoolV01/`; runtime derivatives have new paths. No night window lights have been authored.

Legacy catalog retirement: the image-driven building card grid and its new-placement action were removed from the lot editor. The visible Buildings tool opens the real-time 3D library. Legacy package resolution and selected-building inspection remain so existing saved lots can still load without rewriting their data. The isolated review project compiled, and both SmallSchool3DContentTests passed after this UI change (`legacy-retirement-tests.xml`). The menu itself has not had a fresh visual capture.

Zoom policy remains asset-specific. The schoolhouse explicitly switches from its FBX to directional images at district LOD4 and LOD5. Packaged buildings such as Ivy Townhouse contain mesh representations through package LOD4 and an image representation at package LOD5; Unity's LODGroup selects those by screen size, so a district zoom number alone does not guarantee the chosen package representation. Raw 3D entries without a far-view contract can remain meshes at both levels.
